1产品概述

1.1 背景与问题

旅行场景的用户痛点集中在「信息分散」与「时机错位」：

  • 信息分散：航班信息在短信、酒店在 OTA App、行程在日历、照片在相册——用户需要跨 5+ 应用拼凑行程。
  • 时机错位：出发当天才想起看航班号，到了目的地才查天气，返程时忘了退房时间——每个环节都有「最后一刻才发现」的风险。
  • 回忆断层：旅行结束后照片沉睡在相册，缺少行程回顾的触发点和仪式感。

1.2 产品定位

一句话定义：鸿蒙桌面 4×2 单卡旅行助手，以五阶段状态机驱动，根据旅行时间线自动切换卡片内容，在出行前/交通/游览/返程/回忆五个节点提供恰时、恰需、恰好的信息服务。

卡片不是另一个旅行 App，而是将旅行信息折叠到桌面——用户无需打开任何应用，在桌面即可获取当前阶段最关键的 3~4 条信息，需要详情时右上角 ↗ 拉起全程计划应用页。

2KEP · 关键体验原则

KEP（Key Experience Principles）是贯穿整个产品的六条核心设计准则。每条原则都从 Demo 中的具体交互提炼，可量化、可验收。

01
恰时 · 信息随阶段而至
卡片内容不是静态的「一屏展示所有信息」，而是随旅行时间线自动流转。五个阶段各有独立的信息架构：出行前看倒计时和清单，交通看航班状态流，游览看下一站和附近推荐，返程看出发倒计时和退房提醒，回忆看照片和统计。

验收标准：阶段切换由时间/位置/航班状态信号自动触发，用户无需手动翻页即可获取当前阶段信息。进度条 5 段可点击手动切换，但默认跟随信号。
02
恰需 · 每阶段只放 3~4 条
4×2 卡片可用高度约 152px，减去进度条（8px）、Header（22px）、间距后，内容区约 110px。每阶段只展示当前最关键的 3~4 条信息，杜绝信息过载。

分阶段信息预算：
阶段第 1 条第 2 条第 3 条第 4 条
出行前倒计时大字出发日时间线天气双城清单 chips
交通航线视觉航班号+登机口登机/起飞时间状态进度条
游览下一站信息打车/导航附近推荐×3—

03
恰好 · 单卡足够、拉起才深
卡片桌面态只做信息概览，不试图在 4×2 空间内塞入完整行程。需要看全程计划时，右上角 ↗ 按钮拉起全屏应用页，内含路线地图、按天 Tab、分类地点卡片——类似圆周旅记的深度浏览体验。

层级设计：桌面卡片（3~4 条概要）→ 应用页（按天×按地点的完整行程）→ 地点详情页（单地点的导航/门票/评论）。
验收标准：桌面态可见信息条数 ≤ 4；应用页信息量 ≥ 卡片态的 5 倍；两层之间有明确的视觉过渡动画。
04
可交互 · 清单不是只读标签
出行前和返程阶段的 checklist chips 支持点击切换 ✓ / ×，而非静态展示。绿色 chip = 已完成（机票✓ 酒店✓），橙色 chip = 待办（防晒霜✗ 房卡退还✗）。点击时实时切换状态并跨阶段保留。

交互细节：cursor:pointer + hover 缩放 1.03 + active 缩放 0.97，给点击以物理反馈。event.stopPropagation() 防止误触卡片其他事件。
验收标准：所有 chip 可点击切换；切换后状态跨阶段持久化；视觉上有明确的 done/todo 差异（颜色+图标+文案）。
05
双入口 · 主动规划 + 被动识别
主动规划路径：用户通过小艺语音助手说「我要去大理旅行」→ 小艺解析意图 → 自动创建旅行卡片，卡片上显示「✨ 通过小艺创建」徽章。
被动识别路径：系统检测到机票短信/日历事件/酒店预订等多源信号 → 弹出顶部通知（含证据 chips：✈️机票短信 / 📅日历事件 / 🏨酒店预订）→ 用户轻确认「创建卡片」或「稍后」→ 不直接建卡。

验收标准：被动路径必须经过用户确认，不可静默建卡；通知中展示触发信号的来源证据；主动路径有明确的创建来源标识。
06
情绪收束 · 从信息卡到情绪卡
前四个阶段是信息卡（理性、准确、密度高），第五阶段回忆转为情绪卡：照片网格铺满主体区域、行程统计唤起成就感、迷你 SVG 足迹地图提供空间记忆、归档按钮提供仪式感收束。

验收标准：回忆阶段照片区域 ≥ 卡片内容区 50%；统计数字突出（3天·12景点·248张·42km）；足迹地图为真实示意 SVG（非占位图）；归档按钮为唯一底部操作（取代分享/视频/再出发等多按钮）。

阶段1 · 出行前

  • 倒计时大字「3 天」（34px）+ 目的地标签
  • 出发日时间线预告：07:15 出门 → 07:45 到机场 → 08:15 值机截止 → 08:45 起飞
  • 双城天气：出发城市 + 目的地城市
  • 可交互 checklist：机票 ✓ / 酒店 ✓ / 身份证 ✓ / 防晒霜 ✗

阶段2 · 交通

  • 航线视觉：出发城市代码 → ✈️ 虚线 → 目的地城市代码
  • 航班信息：航班号 + 登机口 + 座位号
  • 登机/起飞时间 + 距登机倒计时
  • 五步状态进度条：值机 ✓ → 安检 ✓ → 登机 ●（当前） → 起飞 → 到达

阶段3 · 游览

  • 下一站信息：名称 + 时间段 + 步行距离 + 门票 + 开放时间
  • 快捷操作：打车 / 导航
  • 附近推荐横排（3 张）：图片 + 名称 + 距离 + 推荐理由 + 分类标签
  • 进度提示：已游 N 站 · 还剩 M 站

阶段4 · 返程

  • 返程航线视觉（方向反转：DLU → KMG）+ 航班号同行
  • 出发时间大字「明天 15:30」（26px）
  • 退房提醒 + 上午安排建议
  • 可交互 checklist：证件 ✓ / 手机 ✓ / 房卡退还 ✗ / 伴手礼 ✗

阶段5 · 回忆

  • 精彩瞬间标题 + 最爱标记
  • 行程统计：3天 · 12景点 · 248张 · 42km · 最高3800m
  • 照片网格：主图（2份宽）+ 2张侧图，带标签
  • 最后一行：迷你 SVG 足迹地图（84×28，5 彩色点+虚线轨迹）+ 归档按钮

FR2 · 双入口路径

路径触发方式创建流程UI 标识
主动规划 用户对小艺说「我要去 XX 旅行」 小艺解析意图 → 直接创建卡片 「✨ 通过小艺创建」徽章（2.5s 后淡出）
被动识别 检测到机票短信/日历事件/酒店预订 顶部通知 → 用户确认 → 创建卡片 通知含证据 chips（信号来源展示）

FR3 · 可交互 Checklist

  • 数据模型：chipState = { 1: {机票:true, 酒店:true, ...}, 4: {证件:true, ...} }
  • 切换逻辑：toggleChip(stage, item) 翻转布尔值 → 重新渲染卡片
  • 视觉反馈：done = 绿色背景 + ✓ 图标；todo = 橙色背景 + ✗ 图标
  • 持久化：状态跨阶段保留（切走再切回来状态不变）
  • 事件隔离：event.stopPropagation() 防止误触卡片跳转

FR4 · 全程计划应用页（圆周旅记风格）

右上角 ↗ 按钮拉起全屏应用页，提供深度行程浏览：

  • 顶部概览卡：蓝紫渐变背景 + 标题 + 3 个统计数字（天数/景点数/照片数）
  • SVG 路线地图（320×140）：地形底图 + 洱海椭圆 + 苍山多边形 + 航班虚线路径 + 本地实线路径 + 7 个地点圆点+标签
  • 按天 Tab：总览 + Day 1/2/3，每 Tab 标注当日距离（24km / 42km / 15km）
  • 地点卡片：时间(50px) | 分类图标(36px 方形) | 名称+详情+距离 | 分类 chip
  • 四类配色：景点(spot)=绿 / 美食(food)=橙 / 交通(transport)=蓝 / 住宿(hotel)=紫

FR5 · 进度条导航

  • 卡片顶部 5 段进度条，对应 5 个阶段
  • 已完成阶段 = 半透明白色；当前阶段 = 纯白 + 发光；未到达 = 低透明度
  • 每段可点击，手动切换到对应阶段

FR6 · 阶段切换动画

  • 切换时 fade-out（opacity:0 + scale:0.96, 250ms）→ 内容替换 → cardIn（opacity:0→1 + scale:0.94→1, 400ms）
  • 动画期间禁用交互，防止快速连点

FR7 · 被动识别通知

  • 顶部下拉式通知（translateY(-200%) → 0，400ms cubic-bezier）
  • 通知含：图标 + 标题 + 正文 + 证据 chips + 双按钮（创建卡片 / 稀后）
  • 点击「创建卡片」→ 通知消失 → 卡片以 cardIn 动画入场

4状态机设计

4.1 阶段流转规则

当前阶段触发信号目标阶段信号类型
出行前出发前 2 小时 / GPS 到达机场交通时间+位置
交通航班状态=降落 / GPS 到达目的地游览航班状态
游览旅行最后一天 / 返程前 12 小时返程时间
返程返程航班状态=降落回忆航班状态
回忆旅行结束后 7 天归档（卡片消失）时间

4.2 手动切换

用户可通过两种方式手动切换阶段：

  1. 点击进度条对应段（5 段均可点）
  2. 控制台阶段按钮（Demo 演示用，正式版移除）

手动切换后，若下一个自动信号到达，仍会自动跳转——手动切换是临时预览，不改变状态机的自动流转逻辑。

8验收标准

8.1 KEP 验收

  • KEP-01 恰时：5 阶段均有独立信息架构，阶段间有自动切换信号定义
  • KEP-02 恰需：每阶段可见信息 ≤ 4 条，无内容溢出卡片边界
  • KEP-03 恰好：桌面态只概览，应用页才深度；两层有明确过渡动画
  • KEP-04 可交互：chip 可点击切换 ✓/×，状态跨阶段保留
  • KEP-05 双入口：主动路径有「小艺创建」徽章；被动路径有证据+确认
  • KEP-06 情绪收束：回忆阶段照片 ≥ 50% 内容区，归档按钮为唯一底部操作

8.2 功能验收

  • FR1 五阶段卡片内容完整，每阶段截图无溢出/空白
  • FR2 主动规划路径展示小艺徽章；被动识别路径展示通知+证据 chips
  • FR3 出行前 4 项 chip + 返程 4 项 chip 均可点击切换
