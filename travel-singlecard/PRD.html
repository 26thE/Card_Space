1产品概述

1.1 背景与问题

旅行场景的用户痛点集中在「信息分散」与「时机错位」：

  • 信息分散：航班信息在短信、酒店在 OTA App、行程在日历、照片在相册——用户需要跨 5+ 应用拼凑行程。
  • 时机错位：出发当天才想起看航班号，到了目的地才查天气，返程时忘了退房时间——每个环节都有「最后一刻才发现」的风险。
  • 回忆断层：旅行结束后照片沉睡在相册，缺少行程回顾的触发点和仪式感。

1.2 产品定位与牵引目标

一句话定义：鸿蒙桌面 4×2 单卡旅行助手，以五阶段状态机驱动，根据旅行时间线自动切换卡片内容，在出行前/交通/游览/返程/回忆五个节点提供恰时、恰需、恰好的信息服务。

卡片不是另一个旅行 App，而是将旅行信息折叠到桌面——用户无需打开任何应用，在桌面即可获取当前阶段最关键的 Top 2 信息，需要详情时右上角 ↗ 拉起全程计划应用页。

产品牵引目标：帮助旅行计划用户更好地完成行程规划（输出结构规整的行程计划，支持增删改查）+ 更直观地查看计划（桌面卡片 Top 2 核心信息 + 应用页全程按天浏览）。

1.3 目标用户

核心画像：计划 3 天及以上长途旅行的用户，需要做行程规划且做行程规划有难度——信息分散在多个平台，不知从何下手，难以拼凑成完整可执行的行程。
用户特征痛点产品解法
长途旅行（≥3天） 行程跨度大，信息量大，无法靠记忆管理 五阶段状态机自动分阶段呈现，每阶段只看当前最关键的 Top 2
需要做行程规划 机票/酒店/景点/餐厅分散在短信、OTA、攻略帖，拼不齐 多源信号自动汇聚为结构化行程，按天×分类组织，支持增删改查
规划有难度 不知道怎么排顺序、时间冲突、遗漏关键节点 应用页提供按天时间线 + 距离统计 + 四分类配色，结构规整一目了然

2KEP · 关键体验原则

KEP（Key Experience Principles，关键体验原则）是贯穿整个产品的九条核心设计准则。每条原则按三段书写——原则定义（为什么）→ 本版本落地（Demo v1.3 中具体怎么做）→ 验收标准（怎么算做到），全部可量化、可回归验证。

01
恰时 · 信息随阶段而至
原则卡片内容不是静态的「一屏展示所有信息」，而是随旅行时间线自动流转——处于什么阶段，就只看什么信息，用户不需要翻找。
落地五个阶段各有独立信息架构：出行前看倒计时和清单，交通看航班状态流，游览看当前地点 + 下一地点预告（一日进度视图），也可切换为站点滑动浏览（景点美图视图），返程看出发倒计时和退房提醒，回忆看照片和统计。
验收阶段切换由时间/位置/航班状态信号自动触发（先到者逻辑），用户无需手动翻页即可获取当前阶段信息；进度条 5 段可点击手动切换，但默认跟随信号。
02
恰需 · 每阶段只展示 Top 2 核心关注
原则4×2 卡片可用高度约 152px，减去进度条（8px）、Header（22px）、间距后，内容区约 110px。每阶段只展示当前用户最关注的 2 条核心信息（Top 2），其余信息收起到应用页——杜绝信息过载，让用户一眼就看到最重要的内容。
落地Top 2 定义规则：按阶段信息预算排序，取每个阶段关注优先级最高的 2 条：
阶段Top 1（最关注）Top 2（次关注）其余（速览与操作）
出行前倒计时大字「3天」可交互 checklist（机票✓酒店✓身份证✓防晒霜✗）出发日时间线、双城天气
交通航线视觉+航班号+登机口五步状态进度条（当前步骤高亮）距起飞倒计时、座位号
游览当前地点+时段+距上站距离下一地点预告+硬约束警示天气/步数速览、六宫格操作（攻略/计划/导航/打车）、出门提醒、已游 N 站进度
返程出发时间大字「明天15:30」可交互 checklist（证件✓手机✓房卡✗伴手✗）退房提醒、上午安排
回忆照片网格（主图+2侧图）迷你 SVG 足迹地图行程统计、归档按钮
验收每阶段桌面态可见核心信息 ≤ 2 条（Top 1 + Top 2）；其余信息仅应用页可见；Top 2 优先级可由系统根据时间/位置自动调整（如航班延误时，Top 1 切换为延误提示）。
03
恰好 · 单卡足够、拉起才深
原则卡片桌面态只做信息概览，不试图在 4×2 空间内塞入完整行程。
落地需要看全程计划时，右上角 ↗ 按钮拉起全屏应用页（路线地图、按天 Tab、分类地点卡片），提供类似圆周旅记的深度浏览体验。游览阶段双视图同样受控：一日进度视图 = 当前 + 下一站两条；景点美图视图 = 左侧滑动区 + 右侧六宫格，不堆叠文字。层级设计：桌面卡片（概要）→ 应用页（按天×地点完整行程）→ 地点详情页（导航/门票/评论）。
验收桌面态可见信息条数 ≤ 4；应用页信息量 ≥ 卡片态的 5 倍；两层之间有明确的视觉过渡动画。
04
可交互 · 清单不是只读标签
原则 checklist 是用户的随身核对工具，必须可操作而非静态展示。
落地出行前和返程阶段的 checklist chips 支持点击切换 ✓ / ×：绿色 chip = 已完成（机票✓ 酒店✓），橙色 chip = 待办（防晒霜✗ 房卡退还✗），点击实时切换并跨阶段保留。游览阶段的蓝色打卡按钮同样可交互（点按纠偏当前站）。交互细节：cursor:pointer + hover 缩放 1.03 + active 缩放 0.97，event.stopPropagation() 防止误触卡片其他事件。
验收所有 chip 可点击切换；切换后状态跨阶段持久化；视觉上有明确的 done/todo 差异（颜色+图标+文案）。
05
双入口 · 主动规划 + 被动识别
原则卡片的创建既不能全靠用户记得去开，也不能由系统自作主张——主动有入口，被动有确认。
落地主动规划路径：用户对小艺说「我要去大理旅行」→ 小艺解析意图 → 自动创建卡片，卡片上显示「✨ 通过小艺创建」徽章。被动识别路径：系统检测到机票短信/日历事件/酒店预订等多源信号 → 弹出顶部通知（含证据 chips：✈️机票短信 / 📅日历事件 / 🏨酒店预订）→ 用户轻确认「创建卡片」或「稍后」→ 不直接建卡。
验收被动路径必须经过用户确认，不可静默建卡；通知中展示触发信号的来源证据；主动路径有明确的创建来源标识。
06
情绪收束 · 从信息卡到情绪卡
原则旅行的终点不是信息，而是回忆——最后阶段要从理性服务转向情绪价值。
落地前四个阶段是信息卡（理性、准确、密度高），第五阶段回忆转为情绪卡：照片网格铺满主体区域、行程统计唤起成就感、迷你 SVG 足迹地图提供空间记忆、归档按钮提供仪式感收束。
验收回忆阶段照片区域 ≥ 卡片内容区 50%；统计数字突出（3天·12景点·248张·42km）；足迹地图为真实示意 SVG（非占位图）；归档按钮为唯一底部操作。
07
可编辑 · 行程计划结构规整、增删改查
原则行程计划不是一次性只读数据，而是用户可自主维护的活文档。
落地全程计划应用页提供增删改查四项操作：增（指定日期/时段新增地点，自动插入正确位置并重排时间线）、删（左滑/长按删除，后续地点自动前移）、改（修改时间/名称/详情/分类，实时重排并重算当天总距离）、查（按天 Tab / 分类 chip / 关键词搜索）。结构规整保证：任何增删改操作后，行程自动保持「按天分组 → 按时间排序 → 四分类着色 → 距离重算」四步一致性。
验收增删改查四项操作均可通过应用页完成；操作后行程自动重排（时间升序+距离重算）；卡片与应用页数据双端同步（应用页改了，卡片 Top 2 同步更新）。
08
Top 2 智能排序 · 最关注信息优先
原则Top 2 不是固定写死，而是由系统根据上下文智能排序——外部条件变化时，卡片始终展示当前最值得关注的信息。
落地排序规则（优先级从高到低）：异常事件（航班延误 → Top 1 切换为延误提示+新起飞时间）＞ 时间临近（距下一节点 < 30 分钟 → Top 1 切换为该节点倒计时）＞ 位置触发（GPS 到达某地点 200m 内 → Top 1 切换为该地点详情）＞ 默认优先（无异常时按预设 Top 1/Top 2 展示）。
验收Top 2 自动排序可在设置中关闭（回退为固定优先）；排序切换有 fade 过渡动画（200ms）；每次 Top 2 变化记录日志，用户可在应用页查看「Top 2 变化历史」。
09
先一步 · 当前地点永远带着下一站
原则游览中用户最常问的不是「这是哪」，而是「待会去哪、要注意什么」。卡片必须同时回答现在 + 下一步，把容易遗忘的约束主动顶到眼前，而不是等用户想起来。
落地① 一日进度视图底部固定「下一 · XX」预告条（含下一节点硬约束，如「建议 11:45 下山」）；② 景点美图视图每个站点带「📏 距上一地点 Nm」距离行；③ 硬约束警示条（琥珀色，右上角）：索道 16:30 停运、建议 11:45 下山等；④ 出门提醒（蓝色 note，右上角，与警示条同位）：早餐后第一站提示「🔑 房卡 · 🧥 外套 别忘带」；⑤ 打卡纠偏：走快走慢点一下蓝色打卡钮，当前站与进度重新对齐。
验收每个站点都有下一地点预告；有硬约束的站点必须展示警示条且不遮挡站点名称；出门提醒仅出现在离开住宿后的第一个站点；打卡后当前站、「当前」蓝标与 7 段进度条同步更新。

FR3 · 可交互 Checklist

  • 数据模型：chipState = { 1: {机票:true, 酒店:true, ...}, 4: {证件:true, ...} }
  • 切换逻辑：toggleChip(stage, item) 翻转布尔值 → 重新渲染卡片
  • 视觉反馈：done = 绿色背景 + ✓ 图标；todo = 橙色背景 + ✗ 图标
  • 持久化：状态跨阶段保留（切走再切回来状态不变）
  • 事件隔离：event.stopPropagation() 防止误触卡片跳转

FR4 · 全程计划应用页（圆周旅记风格）

右上角 ↗ 按钮拉起全屏应用页，提供深度行程浏览：

  • 顶部概览卡：蓝紫渐变背景 + 标题 + 3 个统计数字（天数/景点数/照片数）
  • SVG 路线地图（320×140）：地形底图 + 洱海椭圆 + 苍山多边形 + 航班虚线路径 + 本地实线路径 + 7 个地点圆点+标签
  • 按天 Tab：总览 + Day 1/2/3，每 Tab 标注当日距离（24km / 42km / 15km）
  • 地点卡片：时间(50px) | 分类图标(36px 方形) | 名称+详情+距离 | 分类 chip
  • 四类配色：景点(spot)=绿 / 美食(food)=橙 / 交通(transport)=蓝 / 住宿(hotel)=紫

FR5 · 进度条导航

  • 卡片顶部 5 段进度条，对应 5 个阶段
  • 已完成阶段 = 半透明白色；当前阶段 = 纯白 + 发光；未到达 = 低透明度
  • 每段可点击，手动切换到对应阶段

FR6 · 阶段切换动画

  • 切换时 fade-out（opacity:0 + scale:0.96, 250ms）→ 内容替换 → cardIn（opacity:0→1 + scale:0.94→1, 400ms）
  • 动画期间禁用交互，防止快速连点

FR7 · 被动识别通知

  • 顶部下拉式通知（translateY(-200%) → 0，400ms cubic-bezier）
  • 通知含：图标 + 标题 + 正文 + 证据 chips + 双按钮（创建卡片 / 稀后）
  • 点击「创建卡片」→ 通知消失 → 卡片以 cardIn 动画入场

FR8 · 行程计划增删改查（CRUD）

全程计划应用页支持完整的增删改查四项操作，确保用户可以在旅行全程中灵活调整行程，输出始终结构规整。

增（Add）

  • 入口：应用页某天 Tab 下，长按空白区域或点击底部「+ 添加地点」按钮
  • 表单：名称（必填）+ 时间（必填）+ 分类（景点/美食/交通/住宿四选一）+ 详情（选填）+ 预估距离（选填，可调用地图 API 自动计算）
  • 插入逻辑：按时间自动插入正确位置，后续地点后移；当天总距离重算
  • 卡片同步：若新增地点成为当前阶段的 Top 1 或 Top 2，卡片自动更新

删（Delete）

  • 入口：地点卡片左滑出现删除按钮，或长按弹出菜单 → 「删除地点」
  • 二次确认：弹窗提示「确认删除「XX」？该操作不可撤销」+ 确认/取消
  • 删除后：后续地点自动前移；当天总距离重算；若删除的是当前卡片 Top 2 中的地点，卡片自动补位下一个优先级

改（Modify）

  • 入口：点击地点卡片 → 进入编辑态（字段变为可输入）
  • 可改字段：时间、名称、详情、分类、距离
  • 重排触发：修改时间后自动重排当天时间线；修改分类后自动更新配色和图标
  • 冲突检测：两地点时间间隔 < 15 分钟时提示「时间过近，是否调整？」

查（Query）

  • 按天筛选：Day Tab 切换（总览 / Day 1 / Day 2 / Day 3...）
  • 按分类筛选：分类 chip 切换（全部 / 景点 / 美食 / 交通 / 住宿）
  • 关键词搜索：顶部搜索框按名称模糊匹配，结果高亮
  • 距离排序：可切换按时间排序或按距离排序（查看哪天行程最紧凑）

结构规整保证

任何 CRUD 操作后，行程自动执行四步一致性保证：
① 按天分组 → ② 按时间排序（升序） → ③ 四分类着色（spot绿/food橙/transport蓝/hotel紫） → ④ 距离重算（当天总距离更新到 Tab 标签）
不会出现时间倒挂、分类混乱、距离不匹配。

FR9 · Top 2 智能排序

桌面卡片每阶段的内容不是静态写死，而是由系统根据上下文智能排序，始终展示当前最值得关注的 Top 2。

排序优先级触发条件Top 1 切换为Top 2 切换为
P0 异常事件 航班延误/取消 延误提示 + 新起飞时间 原 Top 1 降级为 Top 2
P1 时间临近 距下一节点 < 30 分钟 该节点倒计时（如「距登机 25 分钟」） 原 Top 1 降级为 Top 2
P2 位置触发 GPS 到达某地点 200m 内 该地点详情（名称+导航） 原 Top 1 降级为 Top 2
P3 默认 无异常/临近/到达 阶段预设 Top 1 阶段预设 Top 2
用户控制：Top 2 自动排序可在设置中关闭（回退为固定优先）；每次 Top 2 变化在应用页有「变更历史」可回看。

4状态机设计

4.1 阶段流转规则

当前阶段触发信号目标阶段信号类型
出行前出发前 2 小时 / GPS 到达机场交通时间+位置
交通航班状态=降落 / GPS 到达目的地游览航班状态
游览旅行最后一天 / 返程前 12 小时返程时间
返程返程航班状态=降落回忆航班状态
回忆旅行结束后 7 天归档（卡片消失）时间

4.2 手动切换

用户可通过两种方式手动切换阶段：

  1. 点击进度条对应段（5 段均可点）
  2. 控制台阶段按钮（Demo 演示用，正式版移除）

手动切换后，若下一个自动信号到达，仍会自动跳转——手动切换是临时预览，不改变状态机的自动流转逻辑。

5用户体验规格 · 卡片触发逻辑

本章将状态机中的「触发信号」展开为完整的用户体验规格——定义每个阶段何时、由什么信号、以什么置信度触发，以及在异常场景下的降级策略。

5.1 信号源矩阵

卡片阶段流转依赖三类信号源，每类信号有不同的采集方式和置信度：

信号类型 信号源 采集方式 置信度 说明
时间信号 航班起飞时间 机票订单 / 短信解析 高 出发前 2h 自动切换到交通阶段；返程前 12h 切换到返程阶段
酒店退房时间 OTA 订单 / 日历事件 高 退房当天 08:00 提醒退房，进入返程准备
旅行结束时间 返程航班到达时间 + 7d 高 触发回忆阶段 → 7 天后自动归档
位置信号 GPS 到达机场 系统围栏（机场 POI 半径 2km） 中 与时间信号取先到者触发阶段切换
GPS 到达目的地 系统围栏（目的地城市中心） 中 航班降落 OR 到达目的地，满足任一即切游览阶段
GPS 离开目的地 系统围栏（目的地城市 → 机场方向移动） 低 辅助信号，用于返程阶段提前提示出发
航班状态信号 航班状态变更 航旅纵横 / 航司 API 实时推送 高 状态变更（值机开放/开始登机/已起飞/已降落）驱动阶段内子状态更新
航班延误/取消 航司 API 推送 高 触发卡片内容紧急更新 + 通知用户

5.2 阶段切换决策流程

每个阶段切换都是一个决策点，系统按以下流程判断是否切换：

阶段 1 → 2（出行前 → 交通）

步骤判断条件动作
①当前时间 ≥ 航班起飞时间 - 2h→ 切换到交通阶段
②GPS 进入机场围栏（半径 2km）→ 切换到交通阶段（即使时间未到 2h）
③以上两者取先到者触发 fade-out → cardIn 动画
④用户手动点击进度条第 2 段→ 临时切换（下一信号到达时自动校正）
设计意图：用「先到者」逻辑确保用户不会错过关键信息——即使 GPS 不精确，时间信号兜底；即使时间记错，到达机场也能触发。

阶段 2 → 3（交通 → 游览）

步骤判断条件动作
①航班状态 = 已降落→ 切换到游览阶段
②GPS 到达目的地城市中心围栏→ 切换到游览阶段（即使航班状态未更新）
③无航班数据时：GPS 到达目的地 + 时间超过预计到达→ 切换到游览阶段（降级模式）

阶段 3 → 4（游览 → 返程）

步骤判断条件动作
①当前日期 = 旅行最后一天→ 当天 08:00 切换到返程阶段
②当前时间 ≥ 返程航班起飞 - 12h→ 切换到返程阶段
③无返程航班数据时：酒店退房日当天→ 08:00 切换到返程阶段（降级模式）

阶段 4 → 5（返程 → 回忆）

步骤判断条件动作
①返程航班状态 = 已降落→ 切换到回忆阶段
②GPS 到达出发城市围栏→ 切换到回忆阶段
③回忆阶段持续 7 天后→ 卡片自动归档（从桌面移除）

5.3 阶段内动态更新规则

阶段切换后，卡片内容并非静态——在同一个阶段内，子状态会随信号实时更新：

阶段 2（交通）状态流实时更新

子状态触发信号卡片变化
值机开放 航司推送 OR 起飞前 3h 状态进度条第 1 步亮绿 ✓，显示「值机已开放」
安检完成 GPS 离开值机区域 / 手动标记 第 2 步亮绿 ✓，当前步骤切到「登机」
开始登机 航司推送 OR 起飞前 30min 第 3 步亮白 ●（脉冲动画），显示登机口和座位
已起飞 航班状态 = 已起飞 第 4 步亮绿 ✓，显示「飞行中 · 预计 XX:XX 降落」
已降落 航班状态 = 已降落 第 5 步亮绿 ✓ → 触发阶段 2→3 切换

阶段 1（出行前）倒计时滚动

时间窗口大字内容信息架构变化
出发前 ≥ 7 天「N 天」天气 + 清单为主
出发前 2~7 天「N 天」加入出发日时间线预告
出发前 < 2h→ 切换到交通阶段—

阶段 3（游览）附近推荐刷新

  • 每 30 分钟刷新一次附近推荐列表（基于当前 GPS）
  • 已游览的景点自动从推荐中排除
  • 日落/日出前 1 小时优先推荐观景类地点
  • 用餐时段（11:00-13:00 / 17:00-19:00）优先推荐美食类地点

5.4 信号优先级与冲突处理

当多个信号同时到达或矛盾时，按以下优先级处理：

优先级信号类型理由
P0（最高）航班状态 API权威数据源，实时性最强
P1时间信号确定性高，不依赖网络
P2GPS 位置信号可能受室内/信号弱影响
P3（最低）用户手动切换临时预览，不改变自动流转
冲突示例：航班 API 显示已降落（P0），但 GPS 仍在高空（P2 数据异常）→ 以 P0 为准，切换到游览阶段。

5.5 边界与异常处理

场景 A：无 GPS 权限

受影响信号降级策略
到达机场围栏仅依赖时间信号（起飞前 2h）触发阶段切换
到达目的地围栏仅依赖航班状态（已降落）触发
附近推荐刷新使用酒店地址作为静态参考点，不实时刷新

场景 B：无航班 API 接入

受影响信号降级策略
航班状态变更仅依赖机票订单上的计划时间 + GPS 辅助
状态流子状态不显示实时进度条，只显示计划时间
航班延误/取消无法实时感知，由用户手动查看

场景 C：离线场景

受影响信号降级策略
所有在线信号使用最后一次同步的缓存数据驱动阶段流转
附近推荐展示离线前缓存的推荐，标注「离线数据」
天气展示离线前最后一次天气数据，标注更新时间

场景 D：多程旅行

场景处理方式
A → B → C 多目的地每个航段独立的阶段 2→3 循环，游览阶段拆分为多个子段
中转航班交通阶段内增加中转节点显示，到达中转城市时短暂进入「中转等待」子状态
高铁替代航班信号源切换为高铁时刻表 + 车站围栏，逻辑结构不变

场景 E：行程变更/取消

场景处理方式
航班改签检测到新航班信息 → 更新时间信号 → 重新计算阶段触发时间
行程取消检测到退票/取消 → 弹出确认通知「行程已取消，是否移除卡片？」
提前结束用户手动归档 → 直接跳到回忆阶段

6加桌引导 · 卡片发现与添加

卡片的核心挑战不是功能本身，而是在用户最需要的时候被发现。本章定义系统在什么场景下、通过什么通道、以什么方式提醒用户「可以加一张旅行卡片到桌面」。

6.1 触发场景矩阵

系统检测到以下信号时，触发加桌引导：

# 触发信号 信号来源 置信度 引导时机
1 机票预订确认 短信解析（含「航班」「起飞」「确认」关键词） 高 短信到达后 5 分钟
2 酒店预订确认 短信/邮件解析（含「酒店」「入住」「确认号」） 高 预订确认后即时
3 日历事件（旅行类） 日历标题含「旅行」「出差」「机票」「酒店」 中 事件创建后 / 出发前 3 天
4 高铁/火车票预订 12306 短信 / 邮件解析 高 订票成功后 5 分钟
5 OTA 行程同步 携程/飞猪/去哪儿 App 推送行程 高 OTA 推送到达后即时
6 小艺语音创建 用户说「我要去 XX 旅行」 高 即时（主动路径，不需二次确认）
7 多信号交叉确认 同时检测到 2+ 信号（如机票短信 + 日历事件） 高 最后一个信号到达后即时
8 出发前 3 天未加卡 已检测到行程但用户未加卡 中 出发前 3 天上午 09:00
9 出发前 1 天未加卡 同上，最后一次提醒 中 出发前 1 天晚间 20:00
设计原则：引导是建议而非强制——每次引导必须包含「创建卡片」「稍后」「不再提醒」三个选项，用户始终保有控制权。

6.2 引导通道

根据信号置信度和用户上下文，选择最合适的引导通道：

通道 展示形式 适用场景 频次限制
系统通知 下拉通知栏，含证据 chips + 创建/稍后按钮 置信度高的首次触发（机票短信/酒店预订） 每次行程最多 1 次
小艺建议气泡 桌面/负一屏小艺入口处弹出建议 用户有使用小艺习惯时 每次行程最多 1 次
卡片中心推荐 长按桌面 → 卡片中心 → 顶部推荐位 用户主动进入卡片中心时 无频次限制（用户主动）
出发前提醒 系统通知，标注「明天出发」 已检测到行程但未加卡，出发前 3 天/1 天 最多 2 次（3 天 + 1 天）
OTA 应用内推荐 携程/飞猪 App 完成页底部推荐位 用户在 OTA App 完成预订时 每次行程最多 1 次

6.4 频次控制与免打扰

规则限制理由
每次行程通知上限 最多 3 次（首次检测 + 出发前 3 天 + 出发前 1 天） 避免过度打扰，3 次覆盖「刚订票」「临近出发」「最后机会」三个节点
免打扰时段 22:00 ~ 08:00 不推送加桌引导 夜间不打扰用户休息
已加卡后停止 用户加卡后立即停止所有后续提醒 目标已达成，不再打扰
「不再提醒」尊重 用户点击「不再提醒」后，该行程不再推送 用户控制权优先
跨行程独立计数 不同行程独立计数，不累计 避免因上次行程拒绝而影响本次
同信号去重 机票短信 + 日历事件指向同一行程时合并为一次 避免重复打扰

6.5 添加流程

用户点击「创建卡片」/「添加到桌面」后的交互流程：

步骤动作动画耗时

②卡片在桌面 4×2 位置以 cardIn 动画入场opacity 0→1, scale 0.94→1400ms
③显示「✨ 通过小艺创建」徽章（主动路径时）opacity 0→1300ms

验收标准：从用户点击「创建卡片」到卡片完全渲染 ≤ 1s；整个过程无白屏/闪烁；卡片入场动画流畅无卡顿。

10验收标准

10.1 KEP 验收

  • KEP-01 恰时：5 阶段均有独立信息架构，阶段间有自动切换信号定义
  • KEP-02 恰需：每阶段桌面态只展示 Top 2 核心信息（游览=当前地点+下一地点预告），其余收起至应用页
  • KEP-03 恰好：桌面态只概览，应用页才深度；两层有明确过渡动画
  • KEP-04 可交互：chip 可点击切换 ✓/×，状态跨阶段保留
  • KEP-05 双入口：主动路径有「小艺创建」徽章；被动路径有证据+确认
  • KEP-06 情绪收束：回忆阶段照片 ≥ 50% 内容区，归档按钮为唯一底部操作
  • KEP-07 可编辑：行程计划应用页支持增删改查四项操作，操作后自动重排+重算
  • KEP-08 Top 2 排序：Top 2 可由异常/时间临近/位置触发自动调整，可在设置中关闭
  • KEP-09 先一步：每站点含下一地点预告+距上站距离；硬约束站点展示警示条；出门提醒仅在首站；打卡纠偏同步进度

10.2 功能验收

  • FR1 五阶段卡片内容完整，每阶段截图无溢出/空白
  • FR2 主动规划路径展示小艺徽章；被动识别路径展示通知+证据 chips
  • FR3 出行前 4 项 chip + 返程 4 项 chip 均可点击切换
  • FR4 应用页：概览卡+路线地图+按天 Tab（3 天+总览）+分类地点卡片
  • FR5 进度条 5 段可点击切换阶段
  • FR6 阶段切换有 fade-out → cardIn 动画
  • FR7 被动通知含证据 chips + 双按钮
  • FR8 增：应用页可新增地点，按时间自动插入正确位置，当天距离重算
  • FR8 删：左滑/长按删除地点，二次确认，后续地点自动前移
  • FR8 改：点击地点进入编辑态，改时间后自动重排，改分类后自动更新配色
  • FR8 查：按天 Tab + 分类 chip + 关键词搜索三种筛选方式均可用
  • FR8 结构规整：任何 CRUD 操作后行程保持按天分组+时间升序+四分类着色+距离重算
  • FR8 双端同步：应用页 CRUD 后卡片 Top 2 同步刷新（延迟 ≤ 200ms）
  • FR9 Top 2 默认排序：每阶段 Top 1 + Top 2 按预设优先级展示
  • FR9 异常升序：航班延误时 Top 1 切换为延误提示，原 Top 1 降级
  • FR9 时间临近：距下一节点 < 30 分钟时 Top 1 切换为倒计时
  • FR9 用户控制：可在设置中关闭 Top 2 自动排序，回退固定优先

10.3 视觉验收

  • 卡片 4×2 横铺，圆角 20px，背景图+渐变遮罩
  • 毛玻璃面板 backdrop-filter:blur(20px)，深色半透明
  • 5 阶段主色：蓝/亮蓝/绿/橙/紫
  • 四分类配色：景点绿/美食橙/交通蓝/住宿紫
  • 回忆阶段足迹地图为真实 SVG（5 彩色点+虚线轨迹+城市标签）
  • 应用页路线地图为 320×140 SVG（洱海椭圆+苍山多边形+航班虚线+7 地点）

10.4 触发逻辑验收

  • 阶段 1→2：出发前 2h 和 GPS 到达机场取先到者触发
  • 阶段 2→3：航班降落 OR GPS 到达目的地，任一信号即切换
  • 阶段 3→4：旅行最后一天 OR 返程前 12h，先到者触发
  • 阶段 4→5：返程航班降落 OR GPS 到达出发城市
  • 阶段 5→归档：回忆阶段持续 7 天后自动移除
  • 信号优先级：航班 API > 时间 > GPS > 用户手动
  • 无 GPS 时降级为纯时间驱动，卡片不报错
  • 无航班 API 时降级为计划时间+GPS，状态流进度条隐藏
  • 离线时使用缓存数据，标注「离线数据」
  • 多程旅行支持多段阶段 2→3 循环
  • 航班改签后自动重新计算阶段触发时间
  • 行程取消后弹出确认通知，不静默删除

10.5 加桌引导验收

  • 机票短信触发后 5 分钟内弹出加桌引导通知
  • 酒店预订触发后即时弹出加桌引导通知
  • 多信号指向同一行程时合并为一次通知（去重）
  • 通知含证据 chips（✈️机票短信 / 📅日历事件 / 🏨酒店预订）
  • 通知三按钮：创建卡片 / 稀后 / 不再提醒
  • 出发前 3 天未加卡 → 上午 09:00 推送提醒
  • 出发前 1 天未加卡 → 晚间 20:00 推送最后一次提醒
  • 22:00~08:00 免打扰时段不推送
  • 用户加卡后立即停止所有后续提醒
  • 用户点「不再提醒」后该行程不再推送
  • 卡片中心推荐位展示旅行卡片 + 行程信息
  • 小艺语音创建路径直接建卡，无需二次确认
  • 从点击「创建卡片」到卡片渲染完成 ≤ 1s
