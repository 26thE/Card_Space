1产品概述

1.1 背景与问题

  • 攻略白做：用户出行前刷大量攻略、收藏一堆店铺和机位，到了现场却想不起来看——收藏夹与当下场景脱节。
  • 时机错位：出门忘带房卡、索道快停运才想起来下山、离开了才发现不好打车——每个环节都有「最后一刻才发现」的风险。
  • 信息分散：航班在短信、酒店在 OTA、行程在脑海——需要跨多个应用拼凑当天安排。

1.2 产品定位

一句话定义：鸿蒙桌面 2×4 单卡旅行助手，以三阶段状态机（出行前 → 游览中 → 回忆）驱动，在桌面提供「当前地点 + 下一地点」的恰时提醒，并把用户收藏的攻略素材在正确的时间地点重新送回眼前。

Slogan：让卡片不再是一个人的便利贴——攻略可一人制作、多人跟随，卡片可分享给同行者。

1.3 卡窗分工（重要边界）

卡片只放「提醒级」数据：行程计划、当前/下一地点、清单、硬约束警示——静态、计划级、低刷新。
航班/火车的实时动态不放在卡片：值机、登机口、延误、检票口、晚点等实时信息，届时由系统实况窗（Live Window）承载，卡片不重复建设。卡片至多保留「08:45 起飞」这类出发提醒文字。

1.4 范围说明

本 PRD 仅覆盖手机框内的桌面卡片：三阶段卡片（含游览双视图）与 ↗ 拉起的全程计划应用页。
Demo 页面中画在手机框外的场景展示卡（美食街多店推荐、住宿票据、观光巴士、出门检查等六张）属于设计探索素材，本期不考虑，不进需求范围。

3KEP · 关键体验原则

KEP（Key Experience Principles，关键体验原则）是贯穿整个产品的八条核心设计准则。每条按三段书写——原则定义（为什么）→ 本版本落地（Demo v2.0 中具体怎么做）→ 验收标准（怎么算做到），全部可量化、可回归验证。

01
恰时 · 三阶段自动流转
原则卡片内容不是静态的「一屏展示所有信息」，而是随旅行时间线自动流转——处于什么阶段，就只看什么信息。
落地三个阶段各有独立信息架构：出行前看倒计时、双城天气和清单；游览中看当前地点 + 下一地点预告（一日进度视图），可切换站点滑动浏览（景点美图视图）；回忆看照片和统计。游览阶段内部再按「一日三餐 + 上午/下午/晚上各一个景点」拆为 7 个时刻，一天 7 次切换。
验收阶段切换由信号自动触发（出发当天 → 游览；行程最后一天 → 回忆；结束后 7 天 → 归档）；顶部 3 段进度条可点击手动切换，但默认跟随信号；游览内部 7 时刻以时间推算为主、打卡纠偏为辅。
02
恰需 · 每阶段只展示 Top 2 核心关注
原则2×4 卡片内容区高度有限，每阶段只展示当前最关注的 2 条核心信息，其余收起到应用页——杜绝信息过载。
落地
阶段Top 1（最关注）Top 2（次关注）其余（速览与操作）
出行前倒计时大字「3 天」可交互清单（机票✓酒店✓身份证✓防晒霜✗）出发日提醒、双城天气、攻略素材入口
游览中当前地点 + 时段 + 距上站距离下一地点预告 + 硬约束警示天气/步数速览、六宫格操作、出门提醒、已游进度
回忆照片网格（主图 + 2 侧图）行程统计精彩瞬间标记、归档按钮
验收每阶段桌面态可见核心信息 ≤ 2 条；其余信息仅应用页可见；异常（如下一节点临近）时 Top 2 自动让位于警示。
03
素材先存 · 攻略是帮记素材的入口
原则攻略的价值不在「看过」，而在「到点能用上」。前期攻略不是阅读行为，而是替未来的自己存素材——卡片是这个收集行为的统一入口。
落地出行前阶段卡片提供 📖 攻略入口：用户刷到攻略（小红书/点评/朋友分享）后收存进来，按「地点 + 类型」归档（店铺、机位、注意事项）。游览中到达对应地点时，卡片浮现关联素材——景点给「云海栈道拐角最出片」，美食街给「收藏 3 家店」，用户自己决定要不要去。
验收收存的素材必须绑定到具体地点；游览中对应站点卡片展示素材摘要（一日进度视图 meta 行 + 六宫格 📖 攻略打开原文）；回忆阶段输出践行统计（攻略 5/7）。
04
先一步 · 当前地点永远带着下一站
原则游览中用户最常问的不是「这是哪」，而是「待会去哪、要注意什么」。卡片必须同时回答现在 + 下一步，把容易遗忘的约束主动顶到眼前。
落地① 一日进度视图底部固定「下一 · XX」预告条（含下一节点硬约束，如「建议 11:45 下山」）；② 景点美图视图每个站点带「📏 距上一地点 Nm」距离行；③ 硬约束警示条（琥珀色，右上角）：索道停运、停止入园、末班公交等；④ 出门提醒（蓝色 note，右上角同位）：早餐后第一站提示「🔑 房卡 · 🧥 外套 别忘带」；⑤ 打卡纠偏：走快走慢点一下蓝色打卡钮，当前站与进度重新对齐。
验收每个站点都有下一地点预告；有硬约束的站点必须展示警示条且不遮挡站点名称；出门提醒仅出现在离开住宿后的第一个站点；打卡后当前站、「当前」蓝标与 7 段进度条同步更新。
05
可交互 · 清单与打卡都不是只读标签
原则清单是随身核对工具，进度是会被现实打乱的计划——都必须可操作而非静态展示。
落地出行前清单 chips 点击切换 ✓ / ×（绿 = 已完成，橙 = 待办），状态跨阶段保留；游览中蓝色打卡按钮点按即推进当前站；7 段迷你进度条点按直接跳站。交互细节：cursor:pointer + hover 缩放 1.03 + active 缩放 0.97，event.stopPropagation() 防止误触。
验收所有 chip 可点击切换且状态持久化；打卡/跳站后当前站、「当前」蓝标、进度条、背景图四处同步更新。
06
卡窗分工 · 提醒在卡、实时在窗
原则桌面卡片和实况窗各司其职：卡片做计划级提醒（低频、主动看一眼就够），实况窗做实时动态（高频刷新、强时效）。卡片不重复造实况窗的轮子。
落地卡片内不出现值机状态、登机口变更、延误、检票口等实时信息；至多保留「08:45 起飞」「建议 13:00 出发」这类计划级提醒文字。航班/火车实时动态届时由系统实况窗呈现，卡片与实况窗同源于一份行程数据。
验收卡片任何阶段无实时状态组件（无状态进度流、无刷新倒计时）；行程数据改动（如改签）后，卡片提醒文字与实况窗信息一致。
07
生成式预览 · 创建过程即产品导览
原则用户答应加桌之前，先要知道「这张卡片能给我什么」。创建过程本身就是最好的介绍位——边看边生成，生成即理解。
落地创建流程采用左文字右卡片的生成式布局：左侧文字逐段讲解（出行前能干什么 → 游览中能干什么 → 回忆能干什么），右侧手机框内对应卡片逐张实时浮现（三阶段卡 + 游览双视图）。用户在确认加桌前就对完整卡片集合建立预期，确认后一键添加到桌面。
验收创建流程中每一张卡片都有对应的左侧讲解文字；卡片浮现顺序与旅程时间线一致；跳过预览也可直接加桌，但默认展示完整预览。
08
情绪收束 · 从信息卡到情绪卡
原则旅行的终点不是信息，而是回忆——最后阶段从理性服务转向情绪价值。
落地前两个阶段是信息卡（理性、准确、密度高），第三阶段回忆转为情绪卡：照片网格铺满主体区域、行程统计唤起成就感（3天·12景点·248张·42km）、精彩瞬间标记、归档按钮提供仪式感收束。
验收回忆阶段照片区域 ≥ 卡片内容区 50%；统计数字突出；归档按钮为唯一底部操作；未践行素材转入「下次再去」清单。

6数据结构

6.1 游览时刻（dayMoments × 7）

游览阶段的 7 个时刻（一日三餐 + 上午/下午/晚上景点 + 收官），是双视图共同的数据源：

字段含义示例
time / period时刻与时段09:30 / 上午景点

next / btn下一地点预告与打卡按钮文案午餐 复兴路美食街 ｜ 建议 11:45 下山 / ✓ 下山去吃饭

6.2 清单状态（chipState）

  • chipState = { 1: {机票:true, 酒店:true, 身份证:true, 防晒霜:false} }，toggleChip() 翻转后重渲染，跨阶段保留

6.3 阶段定义（stages × 3）

  • stages = { 1:出行前, 2:游览中, 3:回忆 }，各含名称/图标/配色/背景/描述/切换信号
  • 顶部进度条按 3 段渲染；curStage 驱动整体切换

7验收标准

7.1 KEP 验收

  • KEP-01 恰时：3 阶段均有独立信息架构，阶段间有自动切换信号定义
  • KEP-02 恰需：每阶段桌面态只展示 Top 2 核心信息，其余收起至应用页
  • KEP-03 素材先存：素材绑定地点；游览中对应站点展示素材摘要；回忆输出践行统计
  • KEP-04 先一步：每站点含下一地点预告+距上站距离；硬约束站点展示警示条；出门提醒仅首站；打卡纠偏同步进度
  • KEP-05 可交互：chip 可点击切换且跨阶段保留；打卡/跳站后四处同步
  • KEP-06 卡窗分工：卡片无实时状态组件，航班/火车实时信息不出现
  • KEP-07 生成式预览：创建流程左文字右卡片，每张卡有讲解，顺序与旅程一致
  • KEP-08 情绪收束：回忆阶段照片 ≥ 50% 内容区，归档按钮为唯一底部操作

7.2 功能验收

  • FR1 三阶段卡片内容完整，每阶段截图无溢出/空白；进度条 3 段可点击
  • FR2 双视图可切换；滑动区轮播/暂停/圆点/警示/距离行正常；六宫格六格完整无遮挡
  • FR3 攻略按钮出现在两视图；素材摘要随站点变化
  • FR4 双入口路径可走通；被动路径有证据 chips + 用户确认；生成式预览逐张浮现
  • FR5 chip 切换持久化；打卡推进、跳站同步
  • FR6 应用页：概览卡+路线地图+按天 Tab+分类地点卡片；CRUD 后自动重排
  • FR7 改签/取消后卡片提醒文字同步更新（待实况窗接口接入后验证）

7.3 视觉验收

  • 卡片 2×4 横铺，圆角 20px，背景图+渐变遮罩，毛玻璃面板 blur(20px)
  • 三阶段主色：蓝 / 绿 / 紫；四分类配色：景点绿/美食橙/交通蓝/住宿紫
  • 警示条琥珀色、出门提醒蓝色、打卡/打车按钮蓝色高亮，语义一致

术语定义
KEPKey Experience Principles，关键体验原则。从 Demo 交互中提炼的八条核心设计准则，按「原则定义 → 本版本落地 → 验收标准」三段书写，可量化验收。
三阶段状态机卡片内容的流转模型：出行前 → 游览中 → 回忆，由信号驱动自动切换，顶部 3 段进度条可手动切换。
卡窗分工桌面卡片承载计划级提醒（静态、低频），实况窗（Live Window）承载航班/火车实时动态（高频、强时效），两者同源不同责。
攻略素材用户前期收存的攻略内容（店铺/机位/注意事项），绑定到具体地点，游览中到点浮现。
生成式预览创建卡片时的左文字右卡片布局：左侧逐段讲解，右侧手机框内卡片逐张浮现，创建过程即产品导览。
双视图游览阶段的两种卡片形态：一日进度视图（当前+下一站，默认）与景点美图视图（左滑动区+右六宫格）。
六宫格景点美图视图右侧的 2×3 网格：☀️天气 / 👣步数（信息格）+ 📖攻略 / 🗓️计划 / 🧭导航 / 🚕打车（操作格）。
硬约束警示站点上的琥珀色提示条（右上角），提示硬性时间/票务约束，如「⚠️ 17:30 停止入园」。
出门提醒离开住宿后第一个站点的蓝色 note（右上角，与警示条同位），如「🔑 房卡 · 🧥 外套 别忘带」。
打卡纠偏一日进度视图的蓝色打卡按钮：实际走得比计划快/慢时点按，当前站、「当前」蓝标与 7 段进度条同步更新。
